# Ruleset: `alienMissions:`

Back to the [ruleset index](Ruleset.md).

**Engine class:** [`RuleAlienMission`](../src/Mod/RuleAlienMission.h) · **List key:** `type` · **Loader:**
[`RuleAlienMission::load`](../src/Mod/RuleAlienMission.cpp)

An alien mission is the geoscape-side *plan* the aliens execute over weeks: a sequence of UFO
**waves** flying [trajectories](Ruleset-UfoTrajectories.md) through a region, crewed by an
[alien race](Ruleset-AlienRaces.md), working toward an **objective** (score, infiltration, build a
base, spawn a mission site, retaliate, supply). Missions are started by
[`missionScripts:`](Ruleset-MissionScripts.md) / [`adhocScripts:`](Ruleset-AdhocScripts.md)
commands (or by the engine itself for retaliation/supply); the tactical battle that eventually
results is defined by an [`alienDeployments:`](Ruleset-AlienDeployments.md) entry.

```yaml
alienMissions:
  - type: STR_ALIEN_TERROR
    points: 10
    objective: 3               # OBJECTIVE_SITE: spawns a terror/mission site
    spawnZone: 3               # region mission zone holding the target cities
    raceWeights:
      0: { STR_SECTOID: 70, STR_FLOATER: 30 }
      6: { STR_SNAKEMAN: 60, STR_SECTOID: 40 }
    waves:
      - ufo: STR_TERROR_SHIP
        count: 1
        trajectory: P7
        timer: 3000
        objective: true        # this wave executes the site spawn
```

Entries **merge** across mods/files by `type`, support `refNode:` inheritance and `delete: true`
(see the [index](Ruleset.md#how-rulesets-load-the-60-second-version)).

## Identity, selection & scoring

| Key | Type | Default | Meaning |
|---|---|---|---|
| `type` | string | — | Unique id, referenced from mission scripts, region `missionWeights`, and saves. |
| `points` | int | 0 | Alien score added to the region/country when a UFO finishes its trajectory or the objective wave completes (skipped for `objective: 2` on despawn). |
| `objective` | int 0–6 | 0 | Mission goal: 0 score, 1 infiltration, 2 alien base, 3 mission site, 4 retaliation, 5 supply, 6 instant retaliation (`MissionObjective`). |
| `missionWeights` | map month→int | empty → 1 | Weight for when the **engine** picks a random mission of a given objective (e.g. a retaliation after a shot-down UFO, via `Mod::getRandomMission`); keys are first months, later entries take over. |
| `raceWeights` | map month→weights | — | Weighted [alien race](Ruleset-AlienRaces.md) choice per starting month; merges by month with inherited entries (weight 0 deletes a race). |
| `interruptResearch` | research id | — | Discovering this [research](Ruleset-Research.md) topic flags the running mission as interrupted (it stops spawning waves). |

### Wave sub-fields (`waves:` list, in order)

Each wave spawns `count` UFOs one at a time; when all waves are done the mission ends (or loops,
for infiltration/supply-style objectives).

| Key | Type | Default | Meaning |
|---|---|---|---|
| `ufo` | string | — | The [`ufos:`](Ruleset-Ufos.md) type to spawn — or an [`alienDeployments:`](Ruleset-AlienDeployments.md) name with a marker (spawns that mission site directly, no UFO), or a dummy name (no UFO, site chosen by texture/`siteType`). |
| `count` | int | 0 | Number of UFOs generated by this wave, sequentially. |
| `trajectory` | string | — | The [`ufoTrajectories:`](Ruleset-UfoTrajectories.md) id these UFOs fly. |
| `timer` | int minutes | 0 | Base delay before each spawn; actual delay is 50–150% of it in 30-minute steps (`(timer/30/2 + RNG(0..timer/30)) × 30`), 0 = immediately. |
| `objective` | bool | false | This wave performs the mission objective (e.g. lands in `spawnZone` and turns into the mission site). |
| `objectiveOnTheLandingSite` | bool | false | The UFO lands at a random point of the (non-point) area and the site spawns exactly there, instead of the area's top-left corner. |
| `objectiveOnXcomBase` | bool | false | The mission site spawns on an X-COM base in the region (or not at all if there is none). |
| `hunterKillerPercentage` | int | −1 | Chance the UFO spawns as a hunter-killer: −1 = use the [UFO's](Ruleset-Ufos.md) own setting, 0 = never, 1–100 = that % chance. |
| `huntMode` | int | −1 | Hunter-killer target preference: −1 = from UFO rule, 0 = hunt interceptors, 1 = hunt transports, 2 = random per spawn. |
| `huntBehavior` | int | −1 | Hunter-killer dogfight retreat rule: −1 = from UFO rule, 0 = flee when losing, 1 = never flee/never crash (destroyed instead), 2 = random per spawn. |
| `escort` | bool | false | This wave's UFOs escort/protect UFOs of the earlier waves. |
| `interruptPercentage` | int % | 0 | Chance that shooting down a UFO of this wave interrupts the whole mission (100 = always). |

## Sites & bases (objectives 2 and 3)

| Key | Type | Default | Meaning |
|---|---|---|---|
| `spawnZone` | int | −1 | Index into the [region's](Ruleset-Regions.md) `missionZones` used to place the site/base; −1 = use the objective waypoint's zone from the trajectory. |
| `siteType` | string | — | Explicit [`alienDeployments:`](Ruleset-AlienDeployments.md) for the spawned site/base; empty = pick dynamically (from the globe texture for sites, or the deployment's base rules). |
| `despawnEvenIfTargeted` | bool | false | The spawned mission site despawns on schedule even while a craft is targeting it. |
| `respawnUfoAfterSiteDespawn` | bool | false | When the site despawns untouched, the original landed UFO reappears and resumes its trajectory. |
| `showAlienBase` | bool | false | A base built by this mission is revealed (discovered) to the player immediately. |

## Retaliation (objectives 4 and 6)

| Key | Type | Default | Meaning |
|---|---|---|---|
| `retaliationOdds` | int % | −1 | Odds that shooting down this mission's UFO triggers a retaliation mission; −1 = engine default (difficulty/region based). |
| `skipScoutingPhase` | bool | false | Retaliation skips its scout waves and goes straight for an X-COM base in the region (objective 4 only). |
| `spawnUfo` | string | — | The [UFO](Ruleset-Ufos.md) type used for the final base-assault run (default: the type of the wave UFO that found the base). |
| `multiUfoRetaliation` | bool | false | Retaliation keeps its already-spawned UFOs coming after the first base defense instead of ending. |
| `multiUfoRetaliationExtra` | bool | false | As above, but keeps *generating* new waves too (implies `multiUfoRetaliation: true`). |
| `ignoreBaseDefenses` | bool | false | The assault UFO skips the base-defense (missile/laser…) phase entirely. |
| `instaHyper` | bool | false | Show hyperwave-style extra info for the assaulting UFO even without a hyperwave decoder detection. |

## Infiltration (objective 1)

| Key | Type | Default | Meaning |
|---|---|---|---|
| `endlessInfiltration` | bool | true | After a country signs the pact, the mission restarts and picks another country forever; `false` = one cycle only. |

## Earth-based operations & gen missions

OXCE lets a mission operate from an alien base on Earth ("operations") instead of from space, and
lets alien bases spawn their own follow-up missions ("gen missions", configured on the base's
[deployment](Ruleset-AlienDeployments.md)).

| Key | Type | Default | Meaning |
|---|---|---|---|
| `operationType` | int 0–6 | 0 | Where the mission operates from: 0 space (vanilla), 1 existing base in region, 2 new base in region, 3 new base in region if none exists, 4 any existing base on Earth, 5 new base if none on Earth, 6 the hunt-mission's own base (`AlienMissionOperationType`); UFOs then start from and return to that base, and the mission aborts if a required base is missing. |
| `operationSpawnZone` | int | −1 | Region `missionZones` index in which to build the operation base when one must be created. |
| `operationBaseType` | string | — | [`alienDeployments:`](Ruleset-AlienDeployments.md) of the operation base to build (required when a new base can be spawned). |
| `targetBaseOdds` | int % | 0 | For gen missions spawned by an alien base: odds of targeting an X-COM base. |
| `regionWeights` | map month→weights | — | For gen missions spawned by an alien base: weighted [region](Ruleset-Regions.md) choice per starting month. |
